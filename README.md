# بلدي — Backend حقيقي

سيرفر حقيقي وآمن يطابق موقع "بلدي" متل ما هو اليوم (فييد منشورات + موافقة مسبقة + لوحة تحكم كاملة). فيه:
- تسجيل دخول للإدارة بكلمة مرور **مشفّرة** (bcrypt) وجلسة دخول آمنة (JWT)
- قاعدة بيانات حقيقية (SQLite) — منشورات، صور، وإعدادات الموقع
- رفع صور فعلي (حتى 4 صور بكل منشور) وتخزينها على السيرفر
- مسارات محمية: بس صاحب جلسة دخول صحيحة (الإدارة) يقدر يشوف/يوافق/يرفض/يحذف المنشورات ويعدّل الإعدادات

## التشغيل محلياً (على جهازك، للتجربة)

يحتاج [Node.js](https://nodejs.org) مثبّت (نسخة 18 أو أحدث).

```bash
cd backend-starter
npm install
node create-admin.js editor "كلمة-مرور-قوية-هون"
node server.js
```

بيصير السيرفر شغال على `http://localhost:3000`

## أهم المسارات (API)

### عامة (بدون تسجيل دخول)
| المسار | الوصف |
|---|---|
| `POST /api/admin/login` | تسجيل دخول الإدارة، بيرجع token |
| `POST /api/posts` | نشر ستاتوس جديد (multipart/form-data، يقبل حتى 4 صور بحقل `images`) |
| `GET /api/posts` | كل المنشورات المنشورة (الموافق عليها) — هاد يلي الفييد بيعرضه |
| `GET /api/config` | إعدادات الموقع (الاسم، الوصف، الشريط العاجل، المناطق، المجالات، الألوان، البانر) |

### إدارة (يحتاج توكن دخول بـ Header: `Authorization: Bearer <token>`)
| المسار | الوصف |
|---|---|
| `GET /api/admin/posts?status=pending` | منشورات حسب الحالة (`pending` / `approved` / `hidden`) |
| `POST /api/admin/posts/:id/approve` | نشر المنشور بالفييد |
| `POST /api/admin/posts/:id/hide` | إخفاء أو رفض المنشور |
| `DELETE /api/admin/posts/:id` | حذف المنشور نهائياً (وصوره) |
| `GET /api/admin/config` | جلب إعدادات الموقع |
| `PUT /api/admin/config` | تحديث إعدادات الموقع (ترسل الحقول يلي بدك تعدلها بس) |

## شكل البيانات (Data Shapes)

**منشور (Post):**
```json
{
  "id": 1,
  "name": "أبو محمد للمقاولات",
  "type": "مقاول",
  "content": "بدنا 3 عمال بناء...",
  "town": "الناصرة",
  "sector": "بناء وتشطيبات",
  "phone": "0501234567",
  "status": "approved",
  "posted_at": "2026-08-08 10:00:00",
  "images": ["/uploads/171234-photo.jpg"]
}
```

**إعدادات الموقع (Config)** — كائن واحد فيه: `siteName`, `tagline`, `ticker` (array نصوص), `towns` (كائن مناطق، كل منطقة فيها array من `{ar, he}`), `sectors` (array من `{ar, he}`), `bgColor`, `banner` (`headingAr/He`, `subAr/He`, `bgColor`, `textColor`, `size`).

## قبل ما تنشر الموقع فعلياً — نقاط أمان مهمة

1. **غيّر `JWT_SECRET`**: بملف `server.js` في سر افتراضي، لازم تحطه كمتغير بيئة (Environment Variable) بالاستضافة، ومش تسيبه بالكود.
2. **HTTPS إلزامي**: أي استضافة جدية (Render, Railway, Vercel, إلخ) بتعطيك HTTPS تلقائياً — تأكد إنه مفعّل.
3. **كلمة مرور قوية للإدارة**: استخدم كلمة مرور طويلة ومختلفة، وما تشاركها بغير قنوات آمنة.
4. **نسخ احتياطي لقاعدة البيانات**: خد نسخة من ملف `data.db` ومجلد `uploads` بشكل دوري.
5. **حدّ لحجم الصور**: مضبوط حالياً على 5 ميجا للصورة الواحدة، 4 صور بحد أقصى بكل منشور — تقدر تغيّرها بملف `server.js`.

## أين ترفعه (الاستضافة)

خيارات بسيطة ومناسبة لمشروع بادئ:
- **Render.com** — عندها خطة مجانية، سهلة الإعداد لمشاريع Node.js
- **Railway.app** — بديل مشابه وسهل
- لاحقاً، لما يكبر الموقع، تقدر تنتقل لاستضافة أقوى (VPS أو AWS/GCP)

⚠️ **ملاحظة مهمة عن التخزين على Render/Railway المجاني:** الخطط المجانية عادة بتمسح الملفات المرفوعة (زي `data.db` و`uploads`) كل ما يعيد السيرفر تشغيل نفسه. لحل دائم، لازم تستخدم قاعدة بيانات مُدارة (managed database) أو تخزين ملفات خارجي (زي Cloudinary للصور) بدل التخزين المحلي. هاي خطوة إضافية لما توصل لمرحلة الاستضافة الفعلية.

## الخطوة الجاية

هاد الـ backend لسا لازم يترّبط مع ملفات الموقع (`index.html` و`admin.html`) — يعني نبدّل كل نداءات `window.storage` بنداءات `fetch()` توصل لهاد السيرفر. هاي خطوة لازم تصير **بعد** ما يصير عندك رابط استضافة حقيقي وشغال، لأنه ما بينفع نجربها بدون سيرفر فعلي نتأكد إنه شغال معه.
